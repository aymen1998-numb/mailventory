Guide

From the first Gmail connection to tuning the parser. Everything here runs on your machine; nothing is sent to a third party.

Quick start

  1. Create a Google app password (2-step verification required).
  2. Paste it into Settings, click Test connection.
  3. Start a sync, then review the result under Emails.

Want to look around first? Seed sample data with python -m app.cli seed-demo — no Gmail account needed.

1. Connect Gmail

This app reads mail over IMAP with a password Google generates for one app. Your normal Google password will not work.

  1. Turn on 2-step verification: myaccount.google.com/security
  2. Create a password at myaccount.google.com/apppasswords. Name it anything.
  3. Copy the 16 characters and paste them into Settings.

Spaces are removed automatically, so pasting abcd efgh ijkl mnop is fine. The password is written to .env in the project folder, in plain text — use a password you can revoke, and never commit that file.

Why a password and not “Sign in with Google”? Google's OAuth scopes for reading mail are restricted, so a client needs a Cloud project, verification and a security review to leave test mode — and test-mode tokens expire every 7 days. For a single-user local tool, an app password is the smaller, more reliable setup.

2. Sync your mail

Two buttons on Settings:

ActionWhat it doesWhen to use it
Sync new PDF mail Continues from the last processed IMAP UID Normal, repeat use
Re-scan all PDF mail Resets the checkpoint and walks the whole mailbox After widening the search query, or a fresh database

The scan opens Gmail's All Mail folder (detected automatically, archived mail included) and only downloads PDF attachments. The default query is has:attachment filename:pdf; any Gmail syntax works, for example has:attachment filename:pdf from:acme.com after:2026/01/01.

Start with a small cap. Set Max emails per sync to 25 for the first run. Emails are fetched one at a time, so a 20,000-message mailbox takes a while. A positive cap resumes on the next run; 0 means no limit.

Mail is opened read-only: nothing is marked as read, moved or deleted. Duplicates are skipped by Message-ID, so re-running is safe.

3. Orders and stock

A parsed PDF becomes an order with line items, and each line item becomes a product. When no order number is found the app generates MAIL-<email>-<n>.

Stock moves exactly once, when an order is marked received. Ingestion never touches stock, and receiving the same order twice does not double it. Corrections belong in the manual adjustment on the Inventory page, which is recorded per product.

Inventory also takes a reorder level per product; anything at or below it is listed on the dashboard. Every change is stored as a stock movement with a reason, so manual edits stay auditable.

4. When a PDF does not parse

Parsing is deliberately rule based, not a magic model. Each attachment gets a status on the Emails page:

StatusMeaningWhat to do
parsedOrder createdNothing
needs_reviewText read, but no line items matchedOpen the extracted text and tune the patterns
needs_ocrNo text layer — a scanned imageInstall the OCR extras, or enter the order by hand
duplicateThat order number already existsNothing — it is a re-send
errorThe PDF could not be openedThe message under the status says why

To support a new supplier layout:

  1. Open the email and expand Extracted text.
  2. If the values are there but unrecognised, adjust the patterns in app/services/pdf_parser.py: ORDER_NUMBER_RE, DATE_RE, TOTAL_RE, ITEM_LINE_RE, or the column words in TABLE_HEADER_HINTS.
  3. Add a case to tests/test_pdf_parser.py (or tests/test_pdf_tables.py) so the layout keeps working.
  4. Re-scan all mail to rebuild the affected orders.

PDFs with ruled tables are read column by column, which is far more reliable than matching single lines. A table is only used when its header row has a description and a quantity column plus a price or total column, so address blocks and signature boxes are ignored.

5. Fillable forms (optional)

Make fillable on an email's attachment writes a copy of the PDF with empty, clickable fields — handy for filling in a supplier's blank order form. It detects where fields should go; it does not read values, so it is not part of parsing.

The work is done by the separate commonforms command, which you install yourself: pipx install commonforms. Then enable it under Settings, section 3. Nothing from that project is bundled or imported here.

6. Troubleshooting

SymptomMost likely causeFix
Gmail login failed: ... Invalid credentials Normal Google password, or app passwords are blocked Use a 16-character app password. If it still fails: Workspace admins can disable them, and Advanced Protection blocks them.
Could not reach imap.gmail.com:993 Network, VPN or proxy blocked the connection Check the connection and retry
A sync is already running Only one sync may run at a time Wait for the progress bar to finish
Test succeeds, but no orders appear No PDFs match the query, or they are unparseable Check the count on the settings page, then the statuses under Emails
Everything is needs_ocr The PDFs are scans with no text layer Install the OCR extras (see README) and set OCR_ENABLED=true
“commonforms command was not found” The optional tool is not installed pipx install commonforms, then retry
The UI looks stale after a code change The server is still running the old code Restart uvicorn, or run it with --reload

7. Where your data lives

PathContents
.envGmail address and app password, plain text. Git-ignored.
data/orderdesk.dbEmails, attachments metadata, products, orders, stock movements
data/attachments/email-<id>/The PDFs saved from your mail, plus any fillable copies

Message bodies are stored locally so you can see what the parser read. Keep the Gmail query narrow if you would rather not keep them. The app binds to 127.0.0.1 only — do not expose it to the internet.

Deleting data/ resets the app. There are no migrations yet, so a schema change also means starting from an empty database.

8. Command line

python -m app.cli sync          # new mail only
python -m app.cli sync --all    # re-scan everything
python -m app.cli ingest --limit 10
python -m app.cli seed-demo     # sample data, no Gmail needed

The sync buttons use the same code, so a background sync and a CLI sync never run at the same time — the app refuses the second one.
